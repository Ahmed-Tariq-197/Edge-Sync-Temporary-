1. 3D Kinematic & Mathematical Model

State estimation operates in 3D Cartesian space in a shared reference frame, accounting for ego-motion uncertainty. RGB remains the primary modality for detection, tracking and identity (SRS SC-02); depth supplies metric 3D position and occlusion geometry for TTO.

1.0 Frames and Conventions

  • map: the shared world frame (common pre-built map; each UGV localizes against it using LiDAR/IMU/encoders via C-10). All exchanged spatial data is expressed here and carries a frame_id.
  • odom: per-robot, drifting, never exchanged.
  • Camera optical frame: X right, Y down, Z forward (depth). The frustum in §1.3 and the deprojection in §6 both use this convention.

1.1 3D State Vector & Covariance

The target state s(k) and covariance Σ(k) at step k follow a 6-DoF constant-velocity kinematic model in map:

s(k) = [x, y, z, ẋ, ẏ, ż]^T (in frame map) Σ(k) = Cov(s(k)) ∈ ℝ^(6x6) s(k+1) = F s(k) + w, w ~ N(0, Q_target)

1.2 Ego-Motion Uncertainty (Measurement-Side Propagation)

Mecanum slippage and vibration corrupt the robot pose, not the target's dynamics. Therefore ego-motion uncertainty enters the measurement covariance rather than the process noise. A camera-frame observation p_c is mapped to map by p_m = T(ξ) p_c with robot pose ξ (covariance Σ_ξ):

R_total = J_c * R_cam * J_c^T + J_ξ * Σ_ξ * J_ξ^T J_c = ∂p_m/∂p_c , J_ξ = ∂p_m/∂ξ Q_total = Q_target (target acceleration noise only)

This keeps the Mahalanobis gate from rejecting valid matches because of chassis motion. The deterministic transform is applied once (via tf2, §6); this section only propagates its uncertainty, so ego-motion is not double-counted.

Cross-robot gating (SRS FR-53): A's transferred covariance already contains A's localization uncertainty (via R_{total}). B's own pose uncertainty enters B's measurement R_{total,B}. The B-side Mahalanobis gate uses S = H \cdot \Sigma_{A,pred}(t_B) \cdot H^T + R_{total,B} without adding \Sigma_\xi directly to positions.

1.3 3D FOV Frustum and Time-to-Occlusion

Let α_fov, β_fov be the horizontal and vertical half-angles of the effective FOV (the narrower of the aligned RGB and depth FOVs):

V_fov = { p_c = (X, Y, Z) | Z > 0, ||p_c||_2 ≤ R_max, |arctan2(X, Z)| ≤ α_fov, |arctan2(Y, Z)| ≤ β_fov }

The Time-to-Occlusion T_TTO is the infimum τ > 0 at which the predicted target position (transformed into the camera frame) leaves V_fov or the camera-to-target ray intersects a known 3D obstacle hull. The decision logic uses the uncertainty-aware lower bound:

T_TTO^safe = max(0, T̂_TTO − k_τ * σ_TTO) (k_τ = 2, planning value)

σ_TTO is obtained by propagating Σ(k) through the prediction horizon. The coverage of this bound is itself an evaluated quantity (TTO calibration, see Phase 5).

2. Handoff Decision & Utility Logic

2.1 Operational Regimes (TTO Trigger Zones)

  • Zone 1: Steady Tracking (T_TTO^safe > 2.50 s): No handoff initiated. Network silence maintained.
  • Zone 2: Proactive Trigger (1.23 s ≤ T_TTO^safe ≤ 2.50 s): Feasibility evaluated; HANDOFF_RECOMMENDED is emitted if a candidate passes the feasibility test below.
  • Zone 3: Critical Boundary (T_TTO^safe < 1.23 s): Starting a new handoff is forbidden because the full budget no longer fits. An already-running transaction continues under the watchdog (§3.3).

The 1.23 s boundary equals the total budget Δt_budget^max of §3.2, so the zone boundary and the feasibility test are the same inequality.

2.2 Threshold-Gated Utility Function

Receiver eligibility is a hard gate, and ranking among eligible receivers is a weighted sum. The gate removes unsafe candidates; it does not scale the scores of eligible ones, so a busy but safe robot (CPU ≤ 90%) is not penalized.

G(j) = 1 if Load_cpu(j) ≤ 90% AND Battery(j) ≥ 15% AND nav_available(j) AND link_fresh(j) 0 otherwise Feasible(j): t̂_exec(j) + Δt_safety ≤ T_TTO^safe U_j = G(j) * Feasible(j) * [ w1*Φ_feas(j) + w2*Φ_FOV(j) + w3*Φ_net(j) ] w = (0.5, 0.3, 0.2), w1 + w2 + w3 = 1 (configurable via C-12)
  • Φ_feas(j) = clip((T_TTO^safe − t̂_exec(j) − Δt_safety) / T_ref, 0, 1), T_ref = 1.0 s: spare time after the expected execution time and the safety margin.
  • Φ_FOV(j) ∈ [0,1]: probability mass of the predicted target path that lies inside j's frustum during the hold window after the expected intercept time.
  • Φ_net(j) = (1 − p_loss(j)) · clip(1 − RTT(j)/RTT_max, 0, 1), from measured link statistics.

If no candidate has U_j > 0, no handoff is initiated. In the two-UGV baseline there is a single candidate and the utility only reports the margin; ranking matters when more UGVs are present.

3. Timing Model & Anti-Deadlock Protections

3.1 Clock Synchronization

Clocks are synchronized with PTP (IEEE 1588v2) where available, otherwise with a software time-sync daemon; the achieved offset δ_sync is measured in Tier 2. The planning value is 2.0 ms, but Wi-Fi without hardware timestamping may not reach it. To keep deadline arithmetic robust, every request carries both an absolute deadline and a relative tto_remaining_ms_at_send; the receiver may use the relative value when its measured offset exceeds the budgeted δ_sync.

Confidence claim (corrected): with k = 3, a Gaussian tail gives about 99.9% one-sided coverage, but the distribution-free (Cantelli) guarantee is only ≥ 90%. Neither is assumed; σ_total and the achieved coverage are determined empirically from Tier 2 latency distributions, and the margin is recomputed (for example from the measured 99th percentile) if they differ.

The acquisition window is therefore ≤ 700 ms, not 1200 ms, and no separate "1.5 s lock" exists: the transaction lock equals the acquisition hard timeout plus the confirmation allowance.

3.3 10 Hz Liveness Watchdog (Anti-Deadlock)

Reliability patch: an owner waiting in COMMITTED, ACQUISITION, or IDENTITY_VERIFICATION would otherwise hang if the receiver suffers a hardware, power or link failure.

During acquisition and verification, the receiver emits ACQ_STATUS (SLEWING / SEARCHING / ACQUIRED) at 10 Hz. The owner arms a watchdog timer = last good heartbeat + 300 ms; three consecutive missed heartbeats abort the transaction (ERR_CANDIDATE_DEAD), with practical detection taking 300–400 ms including scheduling. This saves at most 700 − 300 = 400 ms compared to waiting for the full cutoff. A DDS LIVELINESS lease of 300 ms provides a redundant transport-level signal. The watchdog is armed on receipt of HANDOFF_RESPONSE=ACCEPT with t_last_good := t_ACCEPT_rx. The acquisition cutoff (700 ms) and T_txn (886 ms) are armed at the same instant.

After an abort: the state machine enters RECOVERY and the owner keeps tracking. A new attempt is allowed only if another eligible candidate exists and the remaining T_TTO^safe ≥ 1.23 s (a full budget). Because detection alone costs ≈ 300 ms, a second attempt is usually infeasible in the two-UGV baseline; the abort's value is to end a doomed transaction early and return control to local recovery rather than waiting out the timeout.

3.4 Ownership Handshake and Epochs

  1. HANDOFF_REQUEST (epoch e) → HANDOFF_RESPONSE. State: COMMITTED; A remains the sole owner.
  2. B streams ACQ_STATUS at 10 Hz, acquires the target, verifies identity and establishes a local track.
  3. B sends HANDOFF_CONFIRM (epoch e, txn T) and starts T_{ack} on its LOCAL MONOTONIC clock (default 100 ms; CONFIRM retransmitted 3 × 30 ms inside this window). A, if T is OPEN, replies HANDOFF_CONFIRM_ACK(new_epoch = e+1), enters CONFIRMED, releases exclusivity and starts T_{claim} (200 ms, local monotonic) at the instant the ACK is sent.
  4. B becomes OWNER only if the ACK is received before T_{ack} expires. On entering TRACKING, B publishes OWNER_CLAIM (role=OWNER, epoch e+1, txn T) on the RELIABLE /{robot_id}/edgesync/ownership_event topic as a burst of 3 copies, 20 ms apart. If T_{ack} expires first, B sends HANDOFF_CANCEL(ACK_TIMEOUT), goes IDLE and IRREVOCABLY ignores any later ACK for T.
  5. A leaves CONFIRMED on the first of: (a) OWNER_CLAIM(epoch e+1, txn T) → STANDBY. (b) HANDOFF_CANCEL(T) → RECOVERY, reclaim IMMEDIATELY at epoch e+2. (c) T_{claim} expiry → RECOVERY, reclaim at epoch e+2.
  6. Epoch arbitration: a robot in OWNER role that receives OWNER_CLAIM or STATE_HEARTBEAT(role=OWNER) with epoch > its own demotes to STANDBY within one control cycle. Highest epoch wins.
  7. Startup invariant: t_{ack\_ms} + owner\_claim\_latency\_budget\_ms < t_{claim\_ms}.

This realizes SRS FR-47 and FR-54: at no time do two UGVs hold exclusive ownership, and a commitment alone never transfers ownership.

3.5 Transaction table and message admission

Each robot keeps a transaction table: OPEN | CLOSED(reason) | CONFIRMED(stored ACK). A transaction leaves OPEN on any transition into RECOVERY, IDLE, STANDBY or TRACKING. CLOSED entries are retained ≥ txn_tombstone_ttl_ms (10 s).

Admission order:

  1. Check protocol_version, frame_id, receiver_id (drop if not self or *).
  2. Transaction lookup: unknown → If msg is HANDOFF_REQUEST, create OPEN record; else drop + log, CLOSED → drop, CONFIRMED + duplicate CONFIRM → replay stored ACK (idempotent; do NOT restart T_{claim}).
  3. Epoch check.
  4. Sequence check.

4. Inter-UGV Protocol & Serialization

4.1 Binary Serialization Mandate

Constraint: all wire messages are serialized with ROS 2 / DDS CDR using custom .msg interfaces. Transmitting the 512-dim float32 Re-ID vector as string-based JSON is prohibited.

4.2 Message Set

Every message begins with a common header (SRS FR-27–FR-30, FR-54):

# Header (common) uint16 protocol_version uint8 message_type string sender_id string receiver_id string transaction_id string target_id uint64 ownership_epoch uint32 sequence int64 stamp_utc_ns # HandoffRequest.msg (Header +) int64 tto_deadline_utc_ns int32 tto_remaining_ms_at_send float32 tto_sigma_ms string frame_id # e.g. "map" float32[3] position # in frame_id float32[3] velocity float32[21] cov_upper_triangle # 6x6 target covariance float32[3] sender_pose # x, y, yaw in frame_id float32[6] sender_pose_cov_ut # 3x3 upper triangle float32[512] reid_feature_vector # L2-normalised OSNet embedding float32 reid_quality # HandoffResponse.msg (Header +) uint8 decision # ACCEPT / REJECT / UNAVAILABLE uint8 reason int32 est_acquisition_ms float32 cpu_load float32 battery # HandoffCancel.msg (Header +) uint8 reason # AcqStatus.msg (Header +) uint8 status; float32 confidence # HandoffConfirm.msg (Header +) float32 reid_similarity; string frame_id; # float32[3] position; float32[21] cov_upper_triangle # HandoffConfirmAck (Header +) uint64 new_epoch # StateHeartbeat.msg (1 Hz telemetry, BEST_EFFORT) HandoffHeader header uint8 role float32 cpu_load float32 battery_pct uint8 nav_status

The request payload is dominated by the 2048-byte embedding and totals roughly 2.5–3 KB including header strings. This exceeds a single Wi-Fi MTU, so FastDDS fragmentation and reliable retransmission apply; the expected transfer time (target < 2 ms) is a Tier 2 measurement target, not a guarantee. If loss sensitivity requires, the embedding can be sent as FP16 or INT8 (≈ 0.5–1 KB) after verifying the accuracy impact.

Spatial fields without a valid frame_id are rejected by the receiver.

5. ROS 2 Execution Blueprint & QoS

Logical components are grouped into four OS processes. Within a process, tightly coupled stages (C-01 → C-02 → C-03) are implemented as one rclpy Node using direct method calls (no DDS hop). Between processes on the same host, Fast DDS uses its shared-memory transport (one copy, not zero-copy). Zero-copy/intra-process composition is NOT used (rclpy limitation).

5.1 Composable Node Graph

  • Node 1: Perception & Kinematics (C-01, C-02, C-03). Continuous; design target 30 Hz with an acceptance threshold fixed by Tier 2 (≥ 15 FPS sustained with the full stack active). Uses TensorRT/CUDA; publishes T_TTO, T_TTO^safe locally.
  • Node 2: Cooperative Handoff FSM (C-04, C-05, C-06, C-09). Event-driven; near-idle until T_TTO^safe falls below 2.50 s or a protocol message arrives.
  • Node 3: Identity & Acquisition (C-07, C-08). The OSNet TensorRT engine is kept resident from startup so no load time falls inside the budget; inference runs on demand, and the owner refreshes a smoothed signature at a low rate so one is always ready. Fallback if Tier 2 shows memory contention: pre-warm at HANDOFF_CANDIDATE (Zone 2) and add the measured load time to Δt_dec.
  • Node 4: Platform & Observability (C-10, C-11, C-12). Pose and covariance in the shared frame, motion/safety execution (including autonomous safe-stop), logging, and parameters.
  • Transport (C-13) is the FastDDS layer configured by the QoS table below; C-14 runs offline off-robot.

6. 2D-to-3D Perception Mechanics

Extracting the 3D target centroid from a 2D detection with a depth-registered RGB-D camera (RGB drives detection, tracking and identity; depth supplies metric position):

  1. 2D Inference: TensorRT-optimized YOLO outputs a box (u_min, v_min, u_max, v_max).
  2. Depth Masking: with depth registered to the color image, take the median of the valid (non-zero) depth pixels in the central 50% of the box to avoid background bleed, giving Z_c. Depth noise grows with range, so its variance is included in R_cam.
  3. Deprojection (pinhole, optical frame X right / Y down / Z forward):
    X_c = (u - c_x) * Z_c / f_x Y_c = (v - c_y) * Z_c / f_y
  4. Frame Transformation: transform [X_c, Y_c, Z_c]^T to map via tf2, using the robot pose interpolated at the image timestamp (not the arrival time). The covariance is propagated as in §1.2, which separates the target's own motion from chassis motion without applying ego-motion twice.
